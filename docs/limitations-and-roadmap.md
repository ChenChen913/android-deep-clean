# 已知限制与后续改进方向

## 0.1 HarmonyOS 相关限制（v1.2）

- HarmonyOS NEXT 不支持 Android APK、adb、Shizuku、Termux；手机端 Agent 暂不可用，只能走电脑端 hdc。
- NEXT 应用沙箱默认不可读；只允许公共目录 `/storage/media/100/local/files` 与媒体库；应用缓存逐文件清理、卸载残留检测不提供。
- `bm clean -c -n <bundle>` 是官方缓存清理能力，但本版本只报告、不自动执行；需要开发者模式并做真机验证。
- hdc 通路的设备授权、断连、超时、公共目录写权限、toybox 命令差异、媒体库 uid/API 差异均未在真实设备验证。
- 媒体库路径由 doctor 探测 `/mnt/data` 下的数字 uid 动态生成，并保留 uid=100 作为回退；多用户/不同版本仍需真机确认。
- 计划哈希已覆盖 platform；旧版本计划必须重新 analyze 和 plan。

## 0. 双通路相关限制（v1.1）

- 电脑端 ADB 通路尚未在本机真机实测（当前环境无 adb/设备）；设备发现、多设备解析、身份绑定、备份/哈希/导出已用 mock 与单元测试覆盖。
- ADB shell 对 Android/data 的可见性依 ROM/版本而异；doctor 只按实际探测报告，不保证所有 Android 11+ 设备都可读。
- 电脑备份为单文件复制（pull）；超大文件/大量文件会较慢，且需要电脑磁盘空间。
- 多设备身份绑定使用 serial+fingerprint+model+sdk 短哈希；同一设备刷机/改指纹后计划会失效，需要重新扫描。
- 设备中途断连会 aborted，但无法保证极小窗口内没有任何已移动文件；journal 会记录，可 verify/restore。
- 电脑端 --hash-mode pc 只拉取“大小相同的重复候选”，不会把全部文件内容拉到电脑。

## 1. 已知限制

### 权限
- 非 Root 无法读 /data/data；部分 ROM 的 Android/data 对 ADB shell 也不可读。
- Android 11+ 的 FUSE 放行是 AOSP 实现细节，不是 API 契约；OEM 可收紧。
- 不申请 MANAGE_EXTERNAL_STORAGE、不自动 root、不修改系统分区。
- SAF 不是本 Skill 的扫描通道；无法全盘读取应用私有缓存。

### 扫描
- 目录档案按路径识别；目录重命名会显示为“未再出现 + 新增”，不会自动识别为同一对象。
- 扫描截断、权限缺口、深度限制、设备环境变化时，档案不做消失判断；这些轮次的差分只作线索。
- 目录档案默认只跟踪 ≥10 MiB 的目录，以及 Android/data、obb、media 下的应用目录；更小的目录不进入跨轮对比。
- 应用版本变化依赖 `pm list packages --show-versioncode`；设备不支持时该字段为空，不做版本变化判断。
- 目录大小是逻辑大小，硬链接在“唯一大小”中只计一次，但目录子树仍按逻辑大小汇总。
- 依赖设备端 find/stat/xargs；不同 toybox 版本/ROM 可能失败或参数差异。
- 文件名含换行等极端字符时，基于行解析的 stat 结果可能缺失。
- 扫描大目录可能超时/截断；会明确报告，不假装完整。
- atime 不可靠；不用“未访问”作为删除证据。
- 无 hash 工具时重复检测降级为大小分组，不能确认完全重复。
- MediaStore 索引可能延迟刷新、缺少路径或标记 pending/trashed；这些差异只作为证据，不能认定文件已删除或可删除。
- MediaStore 查询依赖 shell 权限与 OEM 实现，Android 10/11/12+ 的字段和可用性不同；已在 1 台 HarmonyOS 3.0 兼容版 / Android 10 验证（图片/视频/音频可用，`downloads` 不可用），其他 OEM/版本仍需验证。
- v1.4.0 起 MediaStore 作为辅助索引只读采集，用于交叉验证；文件系统扫描仍是主通道。媒体索引不覆盖未索引文件、应用私有媒体、未挂载卷/其他用户；已在 1 台真机验证，其他机型仍需验证。
- v1.5.0 起增加应用级存储（部分口径）：基础 APK + 外部 data/media/obb；应用内部 data/cache 与 split APK 未计入。未使用 `dumpsys diskstats`（会写系统缓存），也未开发辅助 APK；因此不能给出完整的应用总占用。

### 分析
- 相似图片（非完全重复）不自动识别；只做完全重复、截图/媒体候选，AI 预览后仍需用户确认。
- 应用私有格式/加密缓存无法理解；未知一律保留。
- 卸载残留可能被多用户/工作资料/包名变化误判；CAUTION + 逐包确认。
- 微信/QQ/抖音等路径随版本变化；规则会过时。
- 无法判断照片/视频内容价值；媒体类默认 CAUTION，绝不自动全选。
- 空目录可能是应用占位目录；只做 CAUTION 建议。

### 执行
- 逐文件 mv/rm；超大文件组较慢。
- 隔离不释放空间；需 purge。purge 后不可恢复。
- 恢复依赖本机 .adc-state/journal；状态丢失则无法自动恢复。
- 跨文件系统移动可能失败；失败时源文件保留，报告失败。
- 隔离文件完整性：purge / restore / verify 始终校验大小；只有 execute 使用 `--backup-to` 时才有 SHA-256 内容基准。未备份的执行无法发现“大小相同但内容被替换”的隔离文件。
- 应用可能在清理后立即重建缓存；verify 可能看到源路径重新出现，报告为异常但不算数据丢失。
- 不处理系统级清理（系统缓存分区、ART 编译缓存等）。

### 平台
- 主要验证环境为 Windows + Python 3.13 + mock；真机 ADB 端到端尚未在本环境执行。
- 未在 Android 5–9 老设备上实测。
- 未在微信/QQ 最新版本真机路径上完整验证。

## 2. 后续改进方向

1. **真机兼容性测试矩阵**：多 OEM、多 Android 版本、USB/无线/Shizuku/root；用真实设备补齐 doctor 探测与 toybox 差异。
2. **设备端 helper**：MediaStore 与基础应用级统计已接入；若确实需要完整应用内部 data/cache，下一步再评估带 `PACKAGE_USAGE_STATS` 授权的轻量辅助 APK，并明确权限与维护成本。
3. **感知哈希相似图片**：在用户设备/本机可选计算 dHash/pHash，AI 预览 + 人工确认；不引入重依赖。
4. **聊天应用版本适配**：可配置的路径知识库（微信/QQ/抖音版本差异），更新时不改核心代码。
5. **整目录隔离优化**：对 SAFE cache 目录支持原子 move 整个目录（带 mtime/内容清单校验），减少逐文件开销。
6. **增量扫描**：记录上次快照，只重扫变化目录，提高复查速度。
7. **报告可视化**：生成可折叠 HTML/交互式报告，同时保持 Markdown/JSON 机器可读。
8. **更细的权限分级**：支持 Shizuku 授权状态检测、应用 ops 查询、系统设置跳转。
9. **端到端加密状态目录**：保护 journal 中的路径信息（尤其涉及个人目录）。
10. **多语言**：英文 SKILL.md 与报告模板，扩大平台兼容。
11. **模糊测试**：对 plan/selection/journal 做属性测试，验证任何篡改都无法绕过安全闸门。
12. **备份/导出**：对 CAUTION 项提供加密导出到用户指定目录，再清理设备。

## 3. 不建议的方向

- 用 Root 默认全盘 rm -rf。
- 用文件名/大小/年龄自动判定个人照片/聊天媒体。
- 为“清理量”弱化确认步骤。
- 收集用户文件内容到云端。
