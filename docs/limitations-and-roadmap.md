# 已知限制与后续改进方向

## 1. 已知限制

### 权限
- 非 Root 无法读 /data/data；部分 ROM 的 Android/data 对 ADB shell 也不可读。
- Android 11+ 的 FUSE 放行是 AOSP 实现细节，不是 API 契约；OEM 可收紧。
- 不申请 MANAGE_EXTERNAL_STORAGE、不自动 root、不修改系统分区。
- SAF 不是本 Skill 的扫描通道；无法全盘读取应用私有缓存。

### 扫描
- 依赖设备端 find/stat/xargs；不同 toybox 版本/ROM 可能失败或参数差异。
- 文件名含换行等极端字符时，基于行解析的 stat 结果可能缺失。
- 扫描大目录可能超时/截断；会明确报告，不假装完整。
- atime 不可靠；不用“未访问”作为删除证据。
- 无 hash 工具时重复检测降级为大小分组，不能确认完全重复。
- MediaStore 元数据不完整；本 Skill 使用文件系统扫描，不覆盖未挂载卷/其他用户。

### 分析
- 相似图片（非完全重复）不自动识别；只做完全重复、截图/媒体候选，AI 预览后仍需用户确认。
- 应用私有格式/加密缓存无法理解；未知一律保留。
- 卸载残留可能被多用户/工作资料/包名变化误判；CAUTION + 逐包确认。
- 微信/QQ/抖音等路径随版本变化；规则会过时。
- 无法判断照片/视频内容价值；媒体类默认 CAUTION，绝不自动全选。
- 空目录可能是应用占位目录；只做 CAUTION 建议。

### 执行
- 逐文件 mv/rm；超大文件组较慢。
- 隔离不释放空间；需 purge。purge 后不可恢复。
- 恢复依赖本机 .adc-state/journal；状态丢失则无法自动恢复。
- 跨文件系统移动可能失败；失败时源文件保留，报告失败。
- 应用可能在清理后立即重建缓存；verify 可能看到源路径重新出现，报告为异常但不算数据丢失。
- 不处理系统级清理（系统缓存分区、ART 编译缓存等）。

### 平台
- 主要验证环境为 Windows + Python 3.13 + mock；真机 ADB 端到端尚未在本环境执行。
- 未在 Android 5–9 老设备上实测。
- 未在微信/QQ 最新版本真机路径上完整验证。

## 2. 后续改进方向

1. **真机兼容性测试矩阵**：多 OEM、多 Android 版本、USB/无线/Shizuku/root；用真实设备补齐 doctor 探测与 toybox 差异。
2. **设备端 helper**：用 Shizuku/无障碍/MediaStore 组合提高无电脑场景能力，避免依赖 adb。
3. **感知哈希相似图片**：在用户设备/本机可选计算 dHash/pHash，AI 预览 + 人工确认；不引入重依赖。
4. **聊天应用版本适配**：可配置的路径知识库（微信/QQ/抖音版本差异），更新时不改核心代码。
5. **整目录隔离优化**：对 SAFE cache 目录支持原子 move 整个目录（带 mtime/内容清单校验），减少逐文件开销。
6. **增量扫描**：记录上次快照，只重扫变化目录，提高复查速度。
7. **报告可视化**：生成可折叠 HTML/交互式报告，同时保持 Markdown/JSON 机器可读。
8. **更细的权限分级**：支持 Shizuku 授权状态检测、应用 ops 查询、系统设置跳转。
9. **端到端加密状态目录**：保护 journal 中的路径信息（尤其涉及个人目录）。
10. **多语言**：英文 SKILL.md 与报告模板，扩大平台兼容。
11. **模糊测试**：对 plan/selection/journal 做属性测试，验证任何篡改都无法绕过安全闸门。
12. **备份/导出**：对 CAUTION 项提供加密导出到用户指定目录，再清理设备。

## 3. 不建议的方向

- 用 Root 默认全盘 rm -rf。
- 用文件名/大小/年龄自动判定个人照片/聊天媒体。
- 为“清理量”弱化确认步骤。
- 收集用户文件内容到云端。
